### F2 — book_lesson's error-priority ordering for a combined failure is undocumented/untested

- **Severity**: OBSERVATION
- **Impact**: 🏃 LOW — quick decision; fix is obvious and narrowly scoped
- **Dimension**: Architecture
- **Location**: supabase/migrations/20260901090000_book_lesson_past_scheduled_at.sql:28-40
- **Detail**: The new `SCHEDULED_AT_IN_PAST` guard clause was deliberately placed before the instructor/student existence checks (per the plan's own stated rationale: "rejecting on the cheapest condition first avoids unnecessary lookups for an already-invalid request"). This means a direct RPC call with *both* a past `scheduled_at` and a nonexistent instructor/student now gets `SCHEDULED_AT_IN_PAST` instead of `INSTRUCTOR_NOT_FOUND`/`STUDENT_NOT_FOUND`, a behavior change from before this migration. No test in `book-lesson.test.ts` or `lessons.test.ts` exercises this combined-failure case or pins the ordering. In practice this is unreachable from `createLesson.ts` (which validates instructor/student existence via direct table lookups before ever calling the RPC), so no current caller is affected — this only matters for a hypothetical future direct RPC consumer.
- **Fix**: Optionally add one test to `book-lesson.test.ts` asserting `SCHEDULED_AT_IN_PAST` wins when combined with a nonexistent instructor/student, to pin the intentional ordering for future readers.
- **Decision**: PENDING
